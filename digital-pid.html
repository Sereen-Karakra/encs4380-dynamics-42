From continuous to digital

What happens at every sample?

  1. Measure y[k] and calculate e[k] = r − y[k].
  2. Propose Inew = Iprevious + Ki · Ts · e[k].
  3. Calculate D = Kd · (e[k] − e[k−1]) / Ts.
  4. If anti-windup is enabled, reject an integral increment that would push the command farther beyond a limit.
  5. Apply u[k] = clip(Kp · e[k] + I[k] + D, −Umax, +Umax), then hold it for Ts seconds.

u[k] = Kp·e[k] + Ki·Ts·Σ e[j] + Kd·(e[k] − e[k−1])/Ts   (before limiting; anti-windup OFF)

Initial state: y = 0, I = 0 and previous error = 0. The step is applied at t = 0 and the first control update occurs immediately. The derivative is taken from error, as in the homework equation, so a setpoint step can cause a derivative kick. The plant uses RK4 substeps with a held control command; changing Ts does not change the plant solver accuracy.

Why does a larger Ts matter?

A slow update leaves an old command applied for longer. The controller reacts later to changes and can produce overshoot or oscillations. The effect depends on the plant and gains. Try the sampling preset with Ts = 0.020 s, 0.200 s, and 0.500 s; the comparison keeps the plant and gains fixed.

What does anti-windup change?

An actuator cannot exceed its limit, but an unprotected integral can continue accumulating error. Conditional integration prevents further buildup while allowing the integral to unwind. It cannot make an unreachable setpoint reachable. Try the windup preset and compare both curves.

From simulation to implementation

Arduino PID loop

The sketch uses the selected gains, Ts, setpoint, control limit, and anti-windup setting. The plant is physical, so its model parameters are not used in the controller calculation.

Example hardware adapters use a bipolar analog sensor on A0 and a signed motor command with direction D8 and PWM D9. Calibrate the sensor mapping and adapt these two functions to your encoder and motor driver before using the sketch on your robot.

The controller uses fixed Ts in its equations and a non-blocking micros() scheduler. The loop must run fast enough to service each sample; missed deadlines and real hardware jitter change the response.
